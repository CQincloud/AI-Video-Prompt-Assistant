# AI视频剧本结构化生成提示词知识块

本文档整合并去重自《AI漫剧剧本结构化生成提示词指南》。在本项目中，它用于回答 AI 视频短剧、动漫风格视频、分镜脚本和结构化 JSON 脚本生成问题。

## 结构化剧本解决的问题

用户常见问题包括：AI 只输出自然语言故事，无法直接对接分镜工具；缺少 scene_id、location、characters、action、camera、mood、duration 等字段；角色特征在不同场景中不一致；场景时长不均；镜头语言单调；相邻场景缺少逻辑过渡；JSON 格式不稳定。

解决方向是把“创意”拆成四步：故事大纲、角色设定表、分场景脚本、质量校验。每一步都有固定输入和输出格式，避免一次性让 AI 随意写完整剧本。

## 四步生成流程

第一步：故事大纲。把一句话创意扩展为核心冲突、主要角色、每集概要和故事弧线。必须指定目标受众、风格基调、集数、每集场景数。

第二步：角色设定表。为每个主要角色生成结构化设定，包括姓名、年龄、性格关键词、外貌、标志性特征、AI 绘图提示词。角色设定表是后续分场景脚本和画面生成的一致性约束。

如果剧本后续要进入人物生图或漫剧制作流程，角色设定表中的 AI 绘图提示词不应只是单张正面图提示词，而应包含 three_view_prompt，用于生成该角色的三视图人物卡。角色设定表还应包含 memory_hook 和 visual_anchors，保证角色有记忆点并能在后续分镜中保持一致。

第三步：分场景脚本。把某一集展开为可执行场景数组，每个场景必须包含 scene_id、location、characters、action、dialogue、camera、mood、duration。

第四步：质量检查。检查 JSON 是否可解析，字段是否齐全，时长是否在范围内，镜头是否有变化，角色行为是否符合设定，相邻场景是否有逻辑过渡。

## 故事大纲提示词模板

你是专业 AI 视频短剧编剧。请根据以下创意生成故事大纲。

创意：{一句话创意}

目标受众：{受众}

风格基调：{搞笑/悬疑/治愈/热血/甜宠/古风/科幻}

集数：{N} 集，每集 {M} 个场景

请输出：
1. 核心冲突
2. 主要角色，包含姓名、性格、外貌特征
3. 每集概要，每集 1-2 句话
4. 故事弧线，按起承转合说明

## 角色设定表模板

基于故事大纲，为每个主要角色生成详细设定表。每个角色需要包含：

name：角色姓名

age：年龄

personality：3-5 个性格关键词

appearance：用于 AI 绘图的外貌描述，包含发型、发色、瞳色、服装、体型、标志性特征

memory_hook：一句观众能复述的人设记忆点，例如“外表锋利但眼神像随时想逃跑的漂亮少年”

visual_anchors：把人设记忆点转译成稳定视觉锚点，例如脸型、眼型、眉形、发型、体型、服装剪影、痣、疤、纹样

signature：不可丢失的标志性特征

image_prompt：用于生成角色参考图的提示词

three_view_prompt：用于生成角色三视图人物卡的提示词，必须包含左侧 1/3 面部特写和右侧 2/3 正视图、侧视图、后视图，纯白背景，无文字

negative_prompt：用于角色参考图的负面提示词，例如不要文字、水印、裁切、视图不完整、脸不一致、服装不一致、随机新增配饰、手持道具、夸张动作、夸张表情

输出格式建议为 JSON 数组。角色外观要具体，不要只写“漂亮、帅气、可爱”。如果用户要生成角色模板或人物提示词，three_view_prompt 必须是可复制的最终生图提示词。

## 分场景脚本 JSON 字段

分场景脚本建议输出为 JSON：

episode：集数编号

title：本集标题

scenes：场景数组

每个 scene 包含：

scene_id：场景序号

location：场景地点与氛围，可直接映射为背景提示词

characters：出场角色名称列表

action：角色动作描述，要能映射为视频运动提示词

dialogue：对白内容

camera：镜头语言，包括景别和运镜方式

mood：场景情绪基调

duration：场景时长，单位秒

建议每个场景 3-6 秒；每集 8-15 个场景；camera 至少包含 3 种不同景别，例如特写、近景、中景、全景、远景。

## 分场景脚本提示词模板

你是 AI 视频分镜编剧。请将以下故事大纲的第 {N} 集展开为详细分场景脚本。

故事大纲：{故事大纲}

角色设定：{角色设定表}

本集概要：{第N集概要}

要求：
1. 每个场景包含 scene_id、location、characters、action、dialogue、camera、mood、duration
2. camera 使用标准镜头语言：特写/近景/中景/全景/远景 + 运镜方式
3. duration 单位为秒，每个场景 3-6 秒
4. 每集控制在 8-15 个场景
5. 相邻场景需要有逻辑过渡
6. 输出必须是 JSON，不要输出解释文字

## 质量检查规则

字段完整性：每个场景都必须包含 scene_id、location、characters、action、camera、mood、duration；dialogue 可以为空字符串，但字段应保留。

时长范围：duration 建议在 3-6 秒之间。太短会导致情绪不足，太长会影响短视频节奏。

镜头变化：一集内不要全部使用同一个景别。至少包含特写、近景、中景或全景中的三类。

角色一致性：每集生成时都附上角色设定表，避免角色行为、性格和外观漂移。

场景过渡：相邻场景要有因果关系或情绪递进，避免突然跳转。

JSON 可解析性：输出后应能被 json.loads 或同类工具解析。失败时要求模型只修复 JSON，不重写剧情。

## 常见问题处理

JSON 格式不稳定：在提示词末尾要求“严格按照 JSON Schema 输出，不要包含 Markdown，不要包含解释文字”。

角色不一致：每次生成分场景脚本时附上完整角色设定表，并要求 action 与 dialogue 符合角色性格。

场景跳跃太快：要求相邻场景必须有逻辑过渡，可以加入“人物从上一个地点离开/进入新地点”的过渡动作。

镜头单调：要求每集至少包含三种景别，并在 camera 字段中明确运镜方式。

对白生硬：在角色设定中写清每个角色的说话风格、口头禅和语气。

批量生成效率低：先生成全局故事大纲和角色设定表，再按集并行生成分场景脚本，最后统一格式校验。

## 输出格式建议

回答剧本结构问题时使用：

【结构建议】
说明应采用故事大纲、角色设定表、分场景脚本、质量检查四步。

【字段模板】
给出 JSON 字段和字段含义。

【示例脚本】或【优化后脚本】
用户提供原脚本时输出优化后脚本；用户泛问方法时给一个短示例。

【回答自检】
检查字段是否齐全、时长是否合理、镜头是否有变化、是否可被下游工具解析。
